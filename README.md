# NextTouch

**Copyright (c) 2026 c12n Apps — GPL-2.0-or-later**

NextTouch extends the qemu-ios emulator family — [LightTouch](https://github.com/blake-lucas/LightTouch)
and [mada-02/iOS-Emulator](https://github.com/mada-02/iOS-Emulator), which run
iPhone OS 1 to iOS 7 — toward **iOS 8, 9 and 10**, on Windows, Android and iOS,
from one shared Rust catalog/core.

## Honest status (v0.1.0)

v0.1.0 ships the **picker, catalog, library and settings** on all three
platforms — and no new emulation yet:

- The catalog includes the legacy iPhone OS 1 – iOS 7 devices the baseline
  engine supports, labelled with their real LightTouch status
  (Tested / Tested, slow / Experimental).
- The full iOS 8 / 9 / 10 picker is built in — every device and its final
  firmware per major version, with board, SoC, build, IPSW name, Apple
  download URL and SHA-256 from ipsw.me — and **every iOS 8/9/10 entry is
  labelled "Not booting yet". That is the truth today:** the qemu-ios engine
  implements no SoC newer than the A4, and none of those firmwares boot.
  The picker will only change a label when a firmware has been proven to
  boot (see `docs/COMPATIBILITY.md` for the evidence rule).
- The engine roadmap (`docs/ROADMAP.md`) climbs in versions:
  0.2 kernel alive → 0.3 userland → 0.4 first iOS 8/9 SpringBoard →
  0.5 usable A5 → 0.6 first iOS 10 on A6 → 1.0 qualified matrix, tested
  against six boot milestones (M1 kernel banner … M6 injected tap opens
  Settings). On the one A5 board the firmware ladder is
  5.1.1 → 6.1.3 → 7.1.2 → 8.4.1 → 9.3.5. The catalog also carries an
  internal `stage` per firmware (planned → skeleton → kernel → userland
  → springboard → usable → qualified); every iOS 8/9/10 entry starts at
  `planned`. Graphics for the new versions extend the engine's host GL
  bridge — there is no PowerVR GPU emulation — and 32-bit guests keep
  HFS+ storage and an OpenGL ES UI, which is part of why they come first.
  The 64-bit A7+ path additionally needs a Secure Enclave model and is
  out of scope for this ladder.

## The picker

Two steps everywhere: pick a device, then a firmware. Search filters by
name, identifier, board or SoC. Quick-start defaults are the development
anchors: **iPhone 4S / iOS 8.4.1**, **iPad 2 / iOS 8.4.1**,
**iPhone 5 / iOS 8.4.1**.

The catalog is one JSON file (`crates/nexttouch-catalog/assets/catalog.json`),
generated by `tools/gen_catalog.py` from the [ipsw.me](https://ipsw.me) API
(URLs and SHA-256 recorded from the source at generation time; where a
source publishes no hash, the entry says so — hashes are never invented)
and bundled identically by all three apps.

## Themes

Follow system by default, with a three-state Follow system / Light / Dark
setting on every platform. The theme applies to the app chrome only — an
emulated screen (engine phase) is rendered untinted.

## Privacy

- No telemetry, analytics, crash reporting, accounts, update checks or
  third-party SDKs. v0.1.0 makes no network calls at all.
- The only planned network path is downloading an IPSW **from Apple hosts**,
  on explicit user tap, verified against the catalog's pinned SHA-256
  before use. Firmware is never bundled or redistributed.
- All data lives in app-private storage; the library uses random local
  ids (never guest hardware identifiers); logs never contain paths,
  UDIDs or download URLs with queries. Settings has a
  "Delete all NextTouch data" action everywhere.
- Guest networking is off by default (engine phase rule).

channel** — no stores, no TestFlight.

### The iOS build and JIT

The IPA is sideload-only and must be signed with a **development**
certificate (in Feather or similar): JIT needs `get-task-allow`, which
only development profiles carry. NextTouch follows the JIT method of
[Husk](https://github.com/Leviidev/Husk) (GPL-2.0-or-later, ported with
attribution — see `ios/ios-jit/`): an attached debugger services a
breakpoint RPC and touches every 16 KiB page of the code-cache region;
the region is claimed once at launch (prewarm), then the debugger
detaches. v0.1.0 includes the entitlements, the csops/`CS_DEBUGGED`
detection and a three-state JIT status screen; the prewarm → QEMU handoff
activates with the engine phase and the app says so plainly. The no-JIT
fallback, when the engine lands, is QEMU's TCI interpreter.

## Building

- Catalog: `python3 tools/gen_catalog.py`
- Desktop: `cargo build --release -p nexttouch` (also the source of the
  Windows builds in CI)
- Android: `cd android && ./gradlew assembleRelease` (produces both ABI
  split APKs; the catalog is copied from the Rust crate at build time)
- iOS: `xcodebuild` via `.github/workflows/build-ios.yml` (unsigned;
  Payload zipped into `NextTouch.ipa`)
- Tests: `cargo test` (catalog + core release gates)
